# Проект локальной сети для учебного заведения

## 📌 Контекст проекта
Это курсовая работа по дисциплине «Сети и телекоммуникации». Цель — спроектировать и настроить сеть для вымышленной организации с тремя отделами, размещёнными в двухэтажном здании. Работа выполнена в симуляторе Cisco Packet Tracer.

## 📋 Задание 
В организации 3 отдела:
- Отдел 1 (Комнаты 101-115, 201-217) – 80 человек
- Отдел 2 (Комнаты 218-232) – 10 человек
- Отдел 3 (Все остальные) – 120 человек
- Имеется три внешних адреса из сети 194.54.65.40\29, шлюз 194.54.65.41, днс 8.8.8.8
- Работники отделов имеют сетевой доступ только к компьютерам своего отдела, все работники (кроме отдела 2) имеют доступ в интернет.
- Работники отдела 2 имеют доступ к сетям всех отделов. В организации есть веб-сервер, расположенный в отделе 1(необходимо обеспечить доступ к нему извне).

## 🎯 Решаемые задачи
- Разделение трафика между отделами с помощью VLAN (11, 12, 13).
- Межсетевая маршрутизация через субинтерфейсы на маршрутизаторе (Router-on-a-stick).
- Ограничение доступа между отделами с помощью расширенных ACL:
  - Отделы 1 и 3 видят только свои ресурсы и имеют выход в интернет.
  - Отдел 2 имеет доступ ко всем отделам, но интернет для него запрещён.
- Настройка NAT (Port Address Translation) для выхода в интернет и статического NAT для публикации веб-сервера.
- Автоматическая раздача IP-адресов через DHCP.
  
 ## 📁 Состав репозитория
- `network_topology.pkt` – файл проекта Packet Tracer.
- `configs/` – папка с текстовыми файлами конфигураций маршрутизатора и коммутаторов.
- `screenshots/` – скриншоты с проверкой пингов, работы ACL, NAT.
  
## 🧪 Проверка работоспособности
- Пинг внутри одного отдела — успешен.
- Пинг между разными отделами — запрещён согласно ACL.
- Доступ в интернет из отделов 1 и 3 — разрешён, из отдела 2 — запрещён.
- Внешний доступ к веб-серверу (статический NAT) — работает.
